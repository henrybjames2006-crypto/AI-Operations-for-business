## What changed for the user

A new IT service firm can now be set up from nothing, without the demo companies. One
command creates the company and its owner. The owner then adds the firm's price list,
pricing rules, customers and staff in the app, guided by a checklist on the dashboard.
After that, requests, quotes, approvals and the simulated delivery work for that firm as
they do for the demo companies.

The whole journey is in the [Set up a firm](../setup-a-firm.md) guide. Testing still uses
invented firms.

## Features

### 1. Create a company
- `python -m opsapp company create "Firm name" --timezone Europe/London --owner-name ...
  --owner-email ...` creates an empty company and its first owner.
- It asks for the owner's password and checks it before saving anything.
- It works on a fresh database without `seed`, so a firm's database never contains the
  demo companies.
- Company names are unique. The time zone must be a real one, such as `America/Chicago`.
  The currency is USD.

### 2. First price list
- Importing a price list into a company with no prices yet creates pricing version 1 with
  no rules. The owner approves it as before.

### 3. Pricing rules editor (owner)
- On **Catalog**, the owner adds a volume discount, a minimum charge or a trip fee, or
  removes one.
- Changes go into a draft pricing version. If there is no draft, the first change copies
  the approved version's prices and rules into a new one.
- Nothing changes for quotes until the draft is approved. Quotes already made keep their
  prices.
- A new minimum charge or trip fee replaces the old one. A volume discount replaces one
  for the same service and quantity.
- Values are checked: discounts up to 90%, amounts to the cent, and only services on the
  price list.

### 4. Customers page (owner and operator)
- Add and edit a customer: name, other names, email domains and contact email.
- Add, edit and remove sites.
- Deactivate a customer instead of deleting it, and reactivate it later.
- Requests and quotes that already use a deactivated customer or removed site keep it. New
  requests can't choose it.
- Names, other names and email domains can't overlap between active customers, so the
  reader can always tell customers apart.
- Shared mail services such as gmail.com are refused as a customer's domain, because they
  would match every sender.
- Each customer page lists its changes. Viewers and approvers can see customers but not
  change them.

### 5. Customer CSV import
- One row per site; rows with the same customer name make one customer.
- **Check the file** shows a preview. **Nothing is saved until you click Add these
  customers**, and the file is checked again then.
- The import is all-or-nothing: every problem is listed with its line, and a file with
  any problem saves nothing.
- Cells that would run as spreadsheet formulas are refused.
- It only adds new customers; a name that already exists is reported.
- The import is audited with the file's SHA-256.

### 6. Company settings (owner)
- **Company** changes the company name and time zone.

### 7. Setup checklist
- The dashboard shows **Set up your company** until:
  - a price list is approved;
  - there is at least one customer;
  - there is a second person, so one prepares quotes and another approves them.
- It is not shown for companies that already have all three, such as the demo companies.

### 8. Smaller changes
- Flash messages no longer get lost when two arrive before the next page (a bug from
  0.4.0, found during this build).
- The operator role's description now mentions customers.

## Not in 0.5.0

- No real firm's data was entered. Testing used invented firms.
- No hosting, real email or calendar (unchanged).
- USD only, and no tax calculation (unchanged).
- No import from accounting or PSA tools such as QuickBooks or ConnectWise.
- The customer CSV import adds new customers only; it doesn't update existing ones.
- Deleting a customer or site for good isn't possible; they are deactivated.

## Update to 0.5.0 (Windows PowerShell)

In your project folder, with the virtual environment active:

```powershell
# 1. If this is a new folder, bring your .env along first
Copy-Item "$HOME\Documents\opsapp.env.backup" .\.env

# 2. Install (no new libraries) and update the database
python -m pip install -e ".[dev]"
python -m opsapp db upgrade
python -m pytest -q                    # expect 324 passed
```

**Keep using your current company.** If this is a new folder (empty database), first run
`python -m opsapp seed` and
`python -m opsapp user create --company "Brightline IT Services" --name "Henry" --email henry@example.com`.
Then `python -m opsapp serve`. You will see **Customers** and **Company** in the menu.

**Try setting up an invented firm** in a separate database, as in the
[Set up a firm](../setup-a-firm.md) guide:

```powershell
(Get-Content .env) | Where-Object { $_ -notmatch '^OPSAPP_DATABASE_PATH=' } | Set-Content .env
Add-Content .env "OPSAPP_DATABASE_PATH=data/oakfield.sqlite"
python -m opsapp db upgrade
python -m opsapp company create "Oakfield Computer Care" --timezone Europe/London --owner-name "Olive Owner" --owner-email olive@oakfield.example
python -m opsapp serve
```

To go back to your usual database:

```powershell
(Get-Content .env) -replace '^OPSAPP_DATABASE_PATH=.*', 'OPSAPP_DATABASE_PATH=data/opsapp.sqlite' | Set-Content .env
Copy-Item .env "$HOME\Documents\opsapp.env.backup"   # refresh your .env backup
```
