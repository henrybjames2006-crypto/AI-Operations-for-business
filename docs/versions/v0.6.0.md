## What changed for the user

The things a firm would need before a small pilot, apart from hosting and an independent
review, are now in place:

- backups can leave the computer every day, encrypted, without anyone typing a passphrase;
- a restore can be practised with one command, and the result is recorded;
- an approved quote can reach the customer without the app sending anything: a person
  prints it or copies the email text into their own email program, then records it;
- there are starting drafts for the data agreement and the pilot plan;
- at the end of a pilot, one company's records can be exported and then deleted.

## Features

### 1. Scheduled, encrypted backups to a folder
- `python -m opsapp backup make-key --key FILE` creates a key file (32 random bytes). It
  refuses to replace an existing file.
- `python -m opsapp backup --to-folder DIR --key FILE --keep 14` writes
  `opsapp-YYYYMMDD-HHMMSS.opsbak` into the folder, encrypted with the key (AES-256-GCM),
  then test-restores it and deletes copies beyond the newest 14.
- It refuses a key file inside the backup folder, so a synced folder never holds both.
- If the folder is in OneDrive, the copies leave the computer. The app never uploads
  anything itself.
- Every backup, success or failure, is written to `data\backup.log` and
  `data\backup-status.json`.
- [Backups and restore](../backups.md) has the exact PowerShell commands for a daily
  Windows Task Scheduler job. You run them; the app doesn't change system settings.
- Old passphrase backups (`backup --encrypt`) still work.

### 2. Restore drill
- `python -m opsapp backup drill --folder DIR --key FILE` restores the newest backup into
  a temporary copy and checks:
  - SQLite integrity and the schema version;
  - every company's audit chain;
  - the number of users, customers, workflows and audit events per company. A backup may
    have fewer than the live database (newer work), never more.
- It writes a dated report in `data\drills\`. The live database is never touched.

### 3. Backups on the dashboard (owner)
- **Backups on this computer** shows the last good backup and the last passed drill.
- It warns when the last backup is over 2 days old, the last drill is over 31 days old,
  or the most recent attempt failed.

### 4. Customer copy of an approved quote
- On an approved workflow, **Customer copy and email text** opens a clean page of the
  quote exactly as approved: firm, customer, site, lines, total, "Tax is not included",
  assumptions and the proposed times.
- Print it or save it as a PDF with the browser's Print command (Ctrl+P). The print
  layout hides the menu, banners and email section.
- **Email text** shows the approved To, Subject and body to copy into your own email
  program.
- **Mark as sent by hand** records who sent it, when, how (own email, printed, other) and
  an optional note, in the audit log. The record says the app sent nothing.
- Owners, operators and approvers can record it; viewers can't. A canceled workflow or
  one without an approval has no customer copy.
- The simulated delivery is unchanged and still labelled as a simulation.

### 5. Pilot templates
- [Data agreement template](../pilot/data-agreement-template.md): what data the app holds
  and where, who can see it, AI use, retention and deletion, backups and problem
  reporting. **It is not legal advice** and must be checked by someone qualified before
  anyone signs it.
- [Pilot plan template](../pilot/pilot-plan-template.md): dates, contacts, success
  measures and stop rules, from the pilot checklist.

### 6. Company export and deletion (end of a pilot)
- `python -m opsapp company export "Firm name" --out FILE` writes one company's records to
  JSON. Password hashes, authenticator secrets, sign-in sessions and recovery codes are
  left out.
- `python -m opsapp company delete "Firm name" --out FILE --yes` exports first, then removes
  every row of that company in one transaction. Other companies are untouched.
- Without `--yes` it only prints a warning. Each deletion adds a line to
  `data\deletions.log` with the company id, row count and the export's SHA-256, not the
  name.
- Both are command-line only. There is no button for them in the app.

## Not in 0.6.0

- No hosting or public deployment (still your separate decision).
- No real email sending and no connection to any email or calendar account.
- No independent security review.
- No legal review of the agreement template.
- The backups only leave the computer if the folder is synced (for example OneDrive). The
  app does not check that syncing works.
- The scheduled task runs only while you are signed in to Windows.

## Update to 0.6.0 (Windows PowerShell)

In your project folder, with the virtual environment active:

```powershell
# 1. If this is a new folder, bring your .env along first
Copy-Item "$HOME\Documents\opsapp.env.backup" .\.env

# 2. Install (no new libraries) and update the database
python -m pip install -e ".[dev]"
python -m opsapp db upgrade
python -m pytest -q                    # expect 336 passed
```

If this is a new folder (empty database), also run `python -m opsapp seed` and
`python -m opsapp user create --company "Brightline IT Services" --name "Henry" --email henry@example.com`.

Then set up backups as in [Backups and restore](../backups.md): make the key file, make a
first backup by hand, register the daily task, and run a drill.
