# Version 0.4.0 (Checkpoint 4): Real Sign-in and Hardening

**Version:** 0.4.0
**Checkpoint:** 4
**Date:** 2026-10-06
**Builds on:** [0.3.0](v0.3.0.md)
**Nature:** local prototype with fictional data. Not production ready and not hosted. It
still only listens on 127.0.0.1. Nothing real is sent, scheduled, charged or connected. No
paid AI calls were made while building it.

---

## What changed for the user

The app now has real accounts. People sign in with their email, a password and a 6-digit
code from an authenticator app on their phone. The owner adds people, resets passwords
and phones, and disables accounts.

Backups can be locked with a passphrase and checked by a test restore. The owner can
download the audit log. Tests and security scans run on GitHub for every change.

The old "pick a user" sign-in is still there for the fictional demo, as **demo mode**.

---

## Features

### 1. Password sign-in
- Email and password. Passwords are stored only as scrypt hashes.
- Passwords need at least 12 characters. Common passwords, very simple ones and ones
  containing your name or email are refused.
- After 5 wrong tries the account is locked for 15 minutes. The message never says which
  part was wrong.

### 2. Authenticator app codes
- At first sign-in you scan a QR code with an authenticator app, such as Microsoft
  Authenticator or Google Authenticator. You can also type the key by hand.
- After that, every sign-in asks for the 6-digit code. A code works only once.
- Ten one-time recovery codes are shown once, for when the phone is lost. You can make new
  ones on the Account page.

### 3. Sessions
- Kept on the server.
- They end at sign-out, after 30 minutes without activity, and after 8 hours.
- They also end at once when an owner disables you or resets your password or phone.

### 4. Users page (owners)
- **Add a user** with a role. You get a 16-character temporary password to hand over in
  person. They must choose their own password at first sign-in.
- **Disable and enable** a user.
- **Reset a password**, or **reset an authenticator** so the user sets their phone up again.
- Every change is in the audit log.
- The first owner is created with `python -m opsapp user create`.

### 5. Demo mode
- `OPSAPP_DEMO_MODE=true` brings back the user picker for the fictional data, with an
  orange banner.
- It refuses to start if anyone in the database has a password, so it can't be left on by
  mistake with real accounts.

### 6. Encrypted backups and backup check
- `backup --encrypt` locks the backup with a passphrase you type in, using AES-256-GCM.
  The passphrase is stored nowhere: lose it and the backup can't be opened.
- `backup --verify` opens a backup in a temporary copy and checks it without touching the
  live database. It checks:
  - that it decrypts;
  - the database integrity;
  - the schema version;
  - every company's audit chain.
- Encrypted backups are restored with the same `restore` command.

### 7. Audit log download (owners)
- **JSON**: includes the rule for checking the hash chain. Check it with
  `python -m opsapp audit verify-export audit-log.json`.
- **CSV**: for a spreadsheet.

### 8. Web hardening
- A strict content security policy: no scripts, no inline styles and no framing.
- Pages are never cached.
- Request bodies over about 300 KB are refused.
- The app won't start with real sign-in until `OPSAPP_SESSION_SECRET` is set.

### 9. Automatic checks on GitHub
- Every pull request and every push to main runs:
  - Ruff and mypy;
  - all tests;
  - Bandit, which looks for common Python security mistakes;
  - pip-audit, which looks for known vulnerable dependencies.
- This uses GitHub's free minutes and no secrets.

### 10. Security self-review
- [security-review-0.4.0.md](../security-review-0.4.0.md) goes through the OWASP Top 10,
  covering what was checked, fixed, accepted and still open.
- It is a self-review, not an independent test.

## Not in 0.4.0

- No hosting or public deployment. The app still runs only on your computer.
- No Microsoft 365 or Google sign-in, and no passkeys.
- No emailed password reset: the owner resets passwords.
- Backups are not copied off the machine for you. Save them to a folder such as OneDrive
  yourself.
- No real customer data, email, calendar or payments (unchanged).

## Update to 0.4.0 (Windows PowerShell)

**Important:** after this update the app asks for a password by default. To keep using the
demo users without passwords, turn demo mode on (step 4a).

In your project folder, with the virtual environment active:

```powershell
# 1. If this is a new folder, bring your .env along first
Copy-Item "$HOME\Documents\opsapp.env.backup" .\.env

# 2. Update and install (adds two small libraries)
git pull
python -m pip install -e ".[dev]"

# 3. Update the database and check everything
python -m opsapp db upgrade
python -m pytest -q                    # expect 298 passed
Add-Content .env "OPSAPP_DEMO_MODE=false"
```

Then choose one.

**4a. Demo mode** (the fictional users, no passwords):

```powershell
(Get-Content .env) -replace '^OPSAPP_DEMO_MODE=.*', 'OPSAPP_DEMO_MODE=true' | Set-Content .env
python -m opsapp serve
```

**4b. Real sign-in** (create your own owner, then scan the QR code at first sign-in):

```powershell
python -m opsapp user create --company "Brightline IT Services" --name "Henry" --email you@example.com
python -m opsapp serve
```

After 4b, demo mode won't start on this database, because you now have a password. If you
want both, use a separate database file for the demo.

**Try an encrypted backup:**

```powershell
python -m opsapp backup --out "$HOME\Documents\opsapp-backup.opsbak" --encrypt
python -m opsapp backup --verify "$HOME\Documents\opsapp-backup.opsbak"
Copy-Item .env "$HOME\Documents\opsapp.env.backup"   # refresh your .env backup too
```
