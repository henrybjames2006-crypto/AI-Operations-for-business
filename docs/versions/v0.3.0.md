# Version 0.3.0 (Checkpoint 3): Discovery Kit and Pilot Readiness

**Version:** 0.3.0
**Checkpoint:** 3
**Date:** 2026-10-06
**Builds on:** [0.2.0](v0.2.0.md)
**Nature:** local prototype with fictional data. Not production ready. Nothing real is
sent, scheduled, charged or connected. No paid AI calls were made while building it.

---

## What changed for the user

This version prepares for learning from real IT service firms without putting their data
in the app. It adds a kit for running interviews, a tool on your own computer that strips
personal details from real sample requests, a way to score both readers on those samples,
price list import from a spreadsheet, and a page that measures how long each step takes
and how often people correct the reader. It also fixes the two reading problems found in
the 0.2.0 comparison.

No interviews have been run and no real samples have been collected. Every result below
comes from the fictional demo data.

---

## Features

### 1. Discovery kit (`docs/discovery/`)
- Eight hypotheses to test (H1 to H8), each with what would support or weaken it. All are
  marked untested.
- An interview guide with consent wording, a notes template, an interview tracker (CSV)
  and a labelling guide for sample requests.

### 2. Redaction of sample requests (`python -m opsapp redact`)
- Copies `.txt`, `.eml` and `.md` files into a new folder, replacing emails, phone numbers,
  street addresses, UK postcodes, links, IP addresses, passwords and keys, and every name
  in a names list you write. Originals are never changed.
- The same value gets the same placeholder in every file (`[EMAIL-1]`, `[NAME-2]`).
- Output files are renamed `sample-001.txt` and so on, because file names often hold names.
- Writes `redaction-report.csv` (file, line, kind, placeholder, never the original value)
  and a `labels.csv` template.
- Offline, no AI. It misses things the patterns don't cover, so a person must read every
  redacted file.

### 3. Scoring readers on labelled samples
- `python -m opsapp eval run --samples <folder>` scores the rule-based reader against your
  labels and writes `samples.md` and `samples.json`.
- `eval compare --samples <folder> --yes` adds the AI reader. This sends the redacted text
  to Anthropic and costs money, so the firm must agree first.

### 4. Price list import (Catalog page, owner only)
- Download the current price list as CSV, edit it in Excel, and import it.
- Strict checks: every problem is listed with its line number, and a file with any problem
  saves nothing. Cells starting with `=`, `+`, `@` or a tab are refused, because
  spreadsheets run them as formulas.
- A good file becomes a **draft** pricing version showing new services, changed details and
  services that will no longer be offered. Nothing changes until the owner approves it.
  Only one draft at a time; drafts can be discarded.
- Quotes made earlier keep their old prices.

### 5. Measurements (new page and CSV)
- Time from request received to draft ready, draft to submitted, and submitted to decision,
  taken from the audit log (median, mean, maximum and count).
- For customer, site, services and timeframe: how often people kept, filled in or changed
  what the reader proposed. Recorded for workflows created from 0.3.0 on.
- Visible to everyone in the company, including read-only users. Other companies' workflows
  are never included.

### 6. Pilot checklist (`docs/pilot-checklist.md`)
- What must be true before any pilot with a real firm: sign-in, hosting, backups, data
  terms, AI provider review, and the firm's written agreement. None of it is done yet.

### 7. Fixes from the 0.2.0 comparison
- When a reader gives a customer's full listed name ("Summit Bakery Co") and the request
  uses one of its aliases ("Summit Bakery"), the customer is now accepted. The AI prompt
  also asks for the name exactly as written.
- A site label inside a customer's name ("Bakery" in "Summit Bakery Co") is no longer taken
  as the site.
- The demo guide now says only the owner (Dana Ortiz) sees the dispatcher on the Simulation
  page.

## Verified results

| Check | Result |
| --- | --- |
| Automated tests (no network) | 271 passed |
| Lint (Ruff) and type check (mypy) | clean |
| Rule-based reader, original cases | 40 of 40 fully correct |
| Rule-based reader, held-out cases | 17 of 30 fully correct (was 16); field accuracy 137 of 150 |
| Redaction test sample | all 15 planted details replaced, ordinary numbers and dates kept |
| Price list import, browser check | template download, refused while a draft exists, discard, bad file shows line errors and saves nothing, good file creates a draft, approve applies it |
| Measurements, browser check | empty at first; after one demo workflow shows 0.5 min to draft, customer and timeframe kept, site and services filled in |

The held-out improvement comes from the site fix, which was prompted by held-out case 17,
so that case is no longer an unseen test. The AI comparison was not re-run; doing so costs
about $0.15 and needs your go-ahead.

## Update to 0.3.0 (Windows PowerShell)

In your project folder, with the virtual environment active:

```powershell
git pull
python -m pip install -e ".[dev]"
python -m opsapp db upgrade            # adds one column for imported price lists
python -m pytest -q                    # expect 271 passed
python -m opsapp serve
```

Try the redaction tool on invented files first:

```powershell
mkdir C:\samples\originals
Set-Content C:\samples\originals\one.txt "From jo@example.com: 3 laptops for Jo Smith next week, call 555-014-2233"
Set-Content C:\samples\names.txt "Jo Smith"
python -m opsapp redact C:\samples\originals --out C:\samples\redacted --names C:\samples\names.txt
Get-Content C:\samples\redacted\sample-001.txt
```
