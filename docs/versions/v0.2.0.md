# Version 0.2.0 (Checkpoint 2): Optional AI Request Reader

**Version:** 0.2.0
**Checkpoint:** 2
**Date:** 2026-10-05
**Builds on:** [0.1.0](v0.1.0.md)
**Nature:** local prototype with fictional data. Not production ready. Nothing real is
sent, scheduled, charged or connected. The only external call this version can make is to
the Anthropic API, and only when you turn it on with your own key.

---

## What changed for the user

Requests can now be read by a Claude model instead of the rule-based reader. It is off by
default. When it is on, everything after reading works exactly as in 0.1.0: the AI only
proposes what the request says, and fixed rules still decide customers, prices, approvals
and actions. If the AI is unavailable, fails, or the budget is used up, the request is read
by the rules and the page says so.

---

## Features

### 1. Optional AI reader
- Turn on with `OPSAPP_AI_PROVIDER=anthropic` and `OPSAPP_AI_API_KEY` in your local `.env`.
- Model is a setting: `claude-haiku-4-5` (default, cheapest), `claude-sonnet-5-5` or
  `claude-opus-5-5`.
- The model must answer in a fixed JSON structure. The same checks as before then drop:
  services not in the catalog, quotes not found word for word in the request, customer or
  site names not in the text, and bad quantities or timeframes.

### 2. What the AI sees
- **Sent:** the request text and sender, catalog service names and keywords, customer
  names and aliases, site labels, today's date.
- **Never sent:** prices, user names, other companies' data.
- The request is marked as untrusted customer content. Instruction-like text is reported
  and ignored, never followed.

### 3. Cost controls
- At most 1,500 output tokens per call; requests over the 8,000-token input limit are not
  sent.
- One retry, only for temporary failures (timeout, connection, rate limit, server error).
- An app budget (`OPSAPP_AI_BUDGET_USD`, default $5.00). Once reached, no AI calls are made.
  It is estimated from token counts, so also set a spending limit in the Anthropic console.
- Every call, including failed ones, is recorded with tokens and estimated cost.

### 4. Fallback to rules
- Any failure (budget reached, timeout twice, rejected key, refusal, cut-off or malformed
  answer) falls back to the rule-based reader.
- The workflow page shows a notice with the reason, and the history records an
  `ai_fallback` event.

### 5. Visible usage
- Each workflow page shows the reader used, AI calls, input and output tokens, and
  estimated cost.

### 6. Held-out evaluation cases
- 30 new fictional requests written before either reader ran on them and kept as written.
- The evaluation report now shows reading accuracy separately for the original and the
  held-out cases.

### 7. Reader comparison
- `python -m opsapp eval compare --yes` runs 70 reading cases through both readers and
  reports accuracy, correct next step, manipulation flagged, fallbacks, tokens, cost, and
  every case where they disagree.

### 8. Safer checks for both readers
- Customer and site names suggested by a reader must actually appear in the request text.

## Verified results

| Check | Result |
| --- | --- |
| Automated tests (no network) | 225 passed |
| Lint (Ruff) and type check (mypy) | clean |
| Safety scenarios (approval, failure, duplicate, tenant) | 21 of 21 |
| Rule-based reader, original cases | 40 of 40 fully correct |
| Rule-based reader, held-out cases | 16 of 30 fully correct; field accuracy 137 of 150 |
| AI tests with a fake model | valid answer, malformed answer, invented services, timeout and retry, rejected key, budget reached, refusal, cut-off answer, and a model that "obeys" injected instructions (price, customer and approval unchanged) |
| Live AI comparison | **not run yet**: waiting for Henry's API key |

The held-out result shows the rule-based reader is weak on new wording. Whether the AI
reader does better, and at what cost, is what the live comparison will measure.

## Not in 0.2.0

- No real email, calendar, payments or other external systems (unchanged).
- No real customer data sent to the AI.
- No AI involvement in pricing, approval or customer choice.
- No discovery kit or detailed review-time measurement (Checkpoint 3). The dashboard's
  average time from draft to submission, from 0.1.0, is unchanged.
- Known issue: a site name inside a company name ("Bakery" in "Summit Bakery Co") is taken
  as the site.

## Turn on the AI reader (Windows PowerShell)

After the 0.1.0 setup in the README:

```powershell
python -m pip install -e ".[dev]"      # adds the Anthropic SDK
(Get-Content .env) -replace '^OPSAPP_AI_PROVIDER=.*', 'OPSAPP_AI_PROVIDER=anthropic' | Set-Content .env
$key = Read-Host "Paste your Anthropic API key"
(Get-Content .env) -replace '^OPSAPP_AI_API_KEY=.*', "OPSAPP_AI_API_KEY=$key" | Set-Content .env
Remove-Variable key
python -m opsapp eval compare --yes    # one paid comparison run
python -m opsapp serve
```

If your `.env` was created from the 0.1.0 example, add the new lines from `.env.example`
first (`OPSAPP_AI_API_KEY`, `OPSAPP_AI_MODEL`, `OPSAPP_AI_BUDGET_USD`,
`OPSAPP_AI_TIMEOUT_SECONDS`).
